The route under investigation

Why can a swap complete when its quote does not?

We examined one exact-input route from cUSD to USDT0 through PathUSD. A router needs a quote before execution so it can compare this route with other candidates. If the quote produces no amount, this route cannot take part in that comparison.

PoolManager is the shared Uniswap v4 contract that holds and accounts for pool tokens.

Tempo hook is custom pool code that asks PoolManager for the input token, then uses Tempo's exchange.

The two processes diverge before the first Tempo conversion

The affected quote simulation can reach the hook before the required input balance is prepared. A funded transaction supplies the input first, then runs the same route.

How we tested the explanation

Hypothesis

The missing quote depends on when the hook's input becomes available, not on multi-hop routing or hooks in general.

Ordinary pools

One-hop and two-hop routes test whether multi-hop alone causes the failure.

Fee hooks

Two fee hooks test whether quote simulation skips custom hook calls.

Hook position

Moving the Tempo-style hook from the first pool to the last tests when its input becomes available.

Small real swaps

Small Tempo routes test whether the deployed route always fails. It does not.

Balance boundary

Inputs just above PoolManager's cUSD balance test whether failure follows that balance.

Very large input

A 1,000,000 cUSD input checks genuine Tempo Exchange illiquidity.

What the evidence supports

For certain multi-hop Tempo routes, the examined UniRoute quote path can fail to prepare the balance required by hook execution. An executable route may therefore have no usable quote for route comparison. A fix must produce both an accurate quote and a compatible funded execution plan.

This dashboard does not claim measured production impact, user loss, or better prices. Those claims require production traffic data and same-block comparisons against other executable routes, including gas.
